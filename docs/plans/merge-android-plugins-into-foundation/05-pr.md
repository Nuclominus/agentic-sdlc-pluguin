### Breaking Changes

1. **Marketplace entries:** Reduced from 11 to 4 (7 framework plugins removed as standalone entries)
2. **Skill ids:** All 7 framework skills renamed to `android-foundation:*` namespace (e.g. `retrofit-plugin:retrofit-conventions` → `android-foundation:retrofit-conventions`, including `dagger-plugin:hilt-conventions` → `android-foundation:hilt-conventions`)
3. **Framework plugins no longer independently installable** — they are now rows in the foundation
4. **Telemetry:** `additive_profiles` stack ids preserved (no telemetry break), but skill-id references in config files must be migrated

### Design Properties Preserved

- **Conditional activation:** Retrofit guidance appears only in Retrofit projects; Ktor only in Ktor projects (FR-1 enforced by resolver's dependency checks)
- **Dual-mode resolver equality:** Story 2 test asserts that tree-mode and installed-mode resolve identical `additive_profiles` for the same project — no silent deactivations on production installs
- **Telemetry stability:** Stack ids (`retrofit`, `ktor`, etc.) unchanged; `frameworks.enable/disable` keys preserved
- **Doctor-assisted migration:** `/sdlc:doctor` detects stale `*-plugin:*` skill ids and offers rewrite with explicit approval (no silent breakage; no runtime alias shims)

Reason: The multi-host-port worktree currently enumerates all 7 removed plugin directories in its emitter at `.claude/worktrees/multi-host-port/dist/antigravity/`. A follow-up PR will be needed once that branch lands to update the emitter to reflect the embedded-framework structure.

### Known Open Items (Not Blocking)

1. **De-dup tie-break is order-dependent** — `manifests.mjs` `classify()` de-dup logic mislabels a losing standalone framework with `superseded-by-embedded` reason when two foundations embed the same stack id. Low impact (only one foundation exists today); the new `stack-uniqueness` lint catches the in-repo case if it ever happens.

2. **`minItems: 1` constraint on `frameworks` property** — the schema forbids an empty `frameworks: []` array. Either drop the constraint or ensure `create-pluguin` never emits one (harmless as-is, but worth a future consistency review).

3. **Fixture stale ids** — `tools/sdlc-lint/test/profile.test.mjs` fixtures still reference old `*-plugin:` skill ids (harmless synthetic data; only a false positive for grep-based stale-id hunts, not a runtime issue).

### Release Notes Blurb

The SDLC marketplace now embeds seven Android framework providers (Retrofit, Ktor, Room, DataStore-Proto, Dagger/Hilt, Koin, WorkManager) as rows in `android-foundation`, reducing marketplace entries from 11 to 4. This is a breaking change: skill ids are renamed to the `android-foundation:` namespace (e.g. `retrofit-plugin:retrofit-conventions` → `android-foundation:retrofit-conventions`), and `/sdlc:doctor` will offer migration for existing installs with explicit approval. Dependency-gated activation is preserved — Retrofit projects still receive only Retrofit guidance, Ktor projects only Ktor guidance — through a dual-mode resolver that validates tree-mode and installed-mode produce identical results.
