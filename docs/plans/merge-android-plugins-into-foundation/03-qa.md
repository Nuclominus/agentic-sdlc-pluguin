## Gap analysis (the three candidates named in this call)

1. **Synthesized record's `file` pointing at the foundation's own manifest** — already covered.
   `manifests.test.mjs`'s "edge case 1" test asserts `retrofits[0].file === join(foundationPath,
   "manifest.yaml")`, and Story 2's dual-mode test asserts `deepEqual(t.doc, i.doc)` across both
   loader modes. Adequate; nothing added.

2. **Pass-through fidelity of every optional row key** — **genuine gap, closed.** The existing
   fixture (`embeddedFoundationManifest()` / `SEVEN_FRAMEWORKS`) only ever sets
   `convention_skills` and `phase_injections`; `priority`, `extra_phases`,
   `pre_phase_commands` and `post_pipeline_checks` were never exercised, so a dropped or
   misnamed key in `manifests.mjs`'s conditional-spread block (lines 72-77) would silently
   strip a framework's guidance without failing anything. Added one test exercising all six
   optional keys on one row plus a second row that omits them all, confirming both that present
   keys pass through unchanged and that absent keys are truly omitted (not written as
   `undefined`).

3. **End-to-end resolve: a Retrofit-dependency project resolves `additive_profiles` containing
   `retrofit` and not `ktor`, through the real resolve path** — already covered, and already
   green. `tools/sdlc-lint/fixtures/android-retrofit/expected.json` (`{"foundation":"android",
   "priority":300,"additive":["retrofit"]}`) is loaded by `detect.test.mjs`'s
   `resolveFixture()`, which calls `loadManifests(repoRoot)` — the real, post-move
   `android-foundation/manifest.yaml` with all 7 embedded rows — then `resolveStack()`, the
   same production function `plan.mjs` calls. The strict-equality `additive` comparison means
   `ktor`'s absence is asserted, not merely unchecked. This fixture is not new work from this
   pipeline run; it pre-dates this change and continues to pass unmodified against the merged
   tree, which is itself a meaningful regression signal. Nothing added.
