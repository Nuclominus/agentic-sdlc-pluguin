# Manage Vault (vault lifecycle)

The optional Obsidian vault is the agents' shared knowledge base (they read it when present, and fall
back to the codebase + `docs/plans/` when absent). This skill owns its whole lifecycle in one place:
**scaffold → repair → (re)populate → archive**, all idempotent and content-safe.

Source of truth for plugin-owned files: `${CLAUDE_PLUGIN_ROOT}/vault/` (this plugin ships the template
+ scripts). Install targets in the project: `.obsidian-vault/` and `.claude/scripts/`.

## Plugin-owned vs content — the safety boundary

This is the single most important rule. Only **plugin-owned** files may be added/updated. **Content**
is NEVER auto-modified except `<!-- STUB -->` notes and the generated graph.

| Plugin-owned (may add / offer to update) | Content — NEVER touch |
|---|---|
| `.obsidian-vault/.obsidian/**` (config) | `.obsidian-vault/modules/<name>.md` (filled) |
| `.obsidian-vault/_templates/{module,screen,flow,adr}.md` | `.obsidian-vault/screens/<Name>.md` (filled) |
| `.obsidian-vault/_moc-{root,modules,screens,flows}.md` | `.obsidian-vault/business-logic/<flow>.md` (filled) |
| `.obsidian-vault/README.md` | `.obsidian-vault/architecture/adr-*.md` |
| folder skeleton + `.gitkeep` | `.obsidian-vault/navigation/routes.md` (filled rows) |
| `.claude/scripts/{gen-mermaid,validate-docs,migrate-edges}.mjs`, `check-docs-sync.sh` | `.obsidian-vault/stack/*`, `general/*` |
| `.obsidian-vault/architecture/dependency-graph.md` (generated by gen-mermaid) | any note WITHOUT a `<!-- STUB -->` marker |
| `.obsidian-vault/architecture/ui-patterns.md` (seed — add when MISSING; once it has rows it is content) | (a populated `ui-patterns.md` → content, DIVERGED is reported not overwritten) |

The `<!-- STUB -->` marker (per `${CLAUDE_PLUGIN_ROOT}/rules/documentation.md`) is the boundary inside
the content folders: a note carrying it is an unfilled shell (regeneration may refresh/replace it); a
note without it is human/agent-written content (untouchable).

## Preflight

- **Repo root.** `git rev-parse --show-toplevel` should match CWD; otherwise tell the user to `cd` there.
- **Node.** `command -v node`. The `.mjs` scripts (gen-mermaid/validate-docs/migrate-edges) need it.
  If absent: continue, but skip the Node steps and say so (the vault still works in Obsidian).
- **Vault tracked in git.** `.obsidian-vault/` (and the installed `.claude/scripts/`) must be
  committed / git-tracked — otherwise a `git worktree` used for pipeline isolation never receives
  them and documentation phases run vault-blind (the classic "phases shipped with zero docs" trap).
  If `git check-ignore .obsidian-vault` matches, or `git ls-files .obsidian-vault` is empty, warn and
  recommend tracking it (or completing its submodule registration). Never edit `.gitignore` silently —
  recommend it in the report.
- **Dirty tree.** If `git status --porcelain` is non-empty and the run will write, warn and ask before
  proceeding (unless `--allow-dirty`).
- **`--dry-run`** prints every planned action (what would be added / regenerated / archived) and writes nothing.

## Phases

```
0. Detect state
1. Ensure vault + skeleton      (scaffold if .obsidian-vault/ absent)
2. Verify plugin-owned scaffold (classify: MISSING / IDENTICAL / DIVERGED)
3. Add what is MISSING          (never touch content; DIVERGED → report + offer with diff, never blind-overwrite)
4. Optionally (re)populate docs (content present → regenerate; empty → first populate)
5. Archive before regenerate    (only when phase 4 will rewrite stubs and content exists)
→  Report
```

### Phase 0 — Detect state

Probe and branch:

- `.obsidian-vault/` **absent** → fresh install path (phase 1 scaffolds the full skeleton + scripts).
- Present but **skeleton incomplete** (any plugin-owned scaffold file missing) → repair path (phases 2–3).
- Skeleton complete, **no content** (no non-stub notes in `modules/screens/business-logic`) → offer first **populate** (phase 4, no archive).
- Skeleton complete, **content present** → offer **regenerate** (phase 4, archive first in phase 5).

### Phase 1 — Ensure vault + skeleton

If `.obsidian-vault/` is absent, copy the template verbatim:

```bash
mkdir -p .obsidian-vault
cp -R "${CLAUDE_PLUGIN_ROOT}/vault/obsidian-vault-template/." .obsidian-vault/
mkdir -p .claude/scripts
cp "${CLAUDE_PLUGIN_ROOT}/vault/scripts/"* .claude/scripts/
chmod +x .claude/scripts/*.sh
```

Then go to phase 4's populate branch (a brand-new vault has no content). If `.obsidian-vault/` already
exists, skip to phase 2.

### Phase 2 — Verify plugin-owned scaffold (classify)

For each **plugin-owned** file (the left column above), compare the installed copy `I` against the plugin
source `S` (`${CLAUDE_PLUGIN_ROOT}/vault/...`). There are no template tokens to render in this model
(agents detect project specifics at runtime), so the classification is a plain byte compare:

```
I missing            → MISSING    (plugin ships it; project lacks it → add in phase 3)
sha(I) == sha(S)     → IDENTICAL  (skip)
sha(I) != sha(S):
    if a manifest base proves I was pristine at last install (.obsidian-vault/.vault-manifest.json
       records sha == that base) and S changed  → UPDATED   (safe to refresh, with diff shown)
    else                                          → DIVERGED  (user may have customized → never blind-overwrite)
```

The optional `.obsidian-vault/.vault-manifest.json` records `{plugin_version, files:{relpath: sha256}}`
written at install/update time. Without it, any difference is **DIVERGED** (conservative). Never classify
a content file here — content is out of scope for phases 2–3.

### Phase 3 — Add MISSING; surface DIVERGED safely

- **MISSING** → add the file from `S` (a clean create). `chmod +x` new `.sh`. Show what was added.
- **UPDATED** (manifest-proven) → show the diff; apply only the plugin-owned refresh.
- **DIVERGED** → **never** auto-apply. List under "Needs review" with a short `diff -u` excerpt; only
  overwrite on explicit per-file confirmation.
- **Content files are not considered here at all.**

After writing, record each written file's sha256 into `.vault-manifest.json` so the next run has a base.

### Phase 4 — (Re)populate documentation (optional, user-gated)

This is the ported `fill-vault`: scan the codebase, create/refresh **stub** notes only, regenerate the
graph, flag drift. It NEVER fills section bodies or edge values (`android-docs` owns content) and NEVER
overwrites a non-stub note.

```
4.1 Scan codebase            → see scan.md   (parallel Grep/Glob)
4.2 Diff scan vs vault       → (artifact → target note → absent | stub | filled) + legacy links: notes
4.3 Show summary, ASK        → counts of new stubs / refreshable stubs / drift; require explicit "yes"
    └─ if content exists and the run will refresh existing stubs → run Phase 5 (archive) FIRST
4.4 Apply (idempotent)       → see apply.md  (stubs + navigation/routes.md rows)
4.5 Migrate + generate       → migrate-edges.mjs (dry-run → apply), gen-mermaid.mjs   (Node; skip+note if absent)
4.6 Drift + validation       → see audit.md; run validate-docs.mjs; fold findings into the report
```

**Regeneration is STUB-aware and incremental** (the confirmed default): it creates stubs for code
entities lacking notes, refreshes notes that still carry `<!-- STUB -->`, regenerates the dependency
graph, and flags drift — but leaves every filled (non-stub) note byte-for-byte untouched.

If there is no content yet (fresh/empty vault), this is a first **populate** — same flow, but phase 5
(archive) is skipped (nothing to lose) and there are no stubs to refresh, only to create.

### Phase 5 — Archive before regenerate

Runs automatically **before** phase 4 rewrites any existing stub, only when content exists. See
[archive.md](archive.md). In short: zip the vault's content to
`.obsidian-vault-archives/obsidian-vault-<ISO-timestamp>.zip`, keep the last 5, suggest gitignoring the
archive dir. Report the archive path before proceeding.

## Idempotency

Running `manage-vault` twice on an unchanged project MUST produce zero file changes:
existing scaffold → IDENTICAL (skip); existing notes → skipped (filled) or unchanged (stubs with no new
code); Node scripts are all idempotent. The only writes on a no-op run are none.

## Report

```
manage-vault report (YYYY-MM-DD)
  scaffold:   N added (MISSING), M identical, D diverged (needs review)
  scripts:    N added / updated, Node: present | ABSENT (Node steps skipped)
  populate:   modules +A stubs / S skipped · screens +B / S · flows +C / S · routes +R rows
  refreshed:  K stub notes refreshed (filled notes untouched)
  archive:    .obsidian-vault-archives/obsidian-vault-<ts>.zip  | (none — no regenerate)
  graph:      architecture/dependency-graph.md regenerated | skipped (no Node)
  validation: validate-docs.mjs → clean | F finding(s) (list; escalate layer violations)
  drift:      D notes flagged <!-- DRIFT --> (never deleted)

  Next: invoke `android-docs` to fill the new/refreshed stubs (sections + typed edges) before PR.
```

## Common mistakes (inherited)

- Filling section bodies or edge values → forbidden; `android-docs` owns content. Stubs only.
- Overwriting an existing note → always existence-check; skip filled, refresh only `<!-- STUB -->`.
- Hand-appending MOC bullets → MOCs are Dataview tables; correct frontmatter is the wiring.
- Touching `_templates/`, `architecture/`, `stack/`, `general/` content → out of scope.
- Deleting notes for removed code → never; audit appends `<!-- DRIFT -->`, a human/`android-docs` decides.
- Treating test sources as production → skip `**/src/{test,androidTest,commonTest}/**`, `*Test.kt`, `*Spec.kt`.
- Regenerating without archiving when content exists → phase 5 is mandatory before any stub refresh.
