# PR #210 — protect lint/format configs during an active SDLC run (android-foundation)

> `feat` · merged 2026-09-23 · by @Nuclominus

## Summary

- New `PreToolUse`/`Edit|Write` hook `plugins/android-foundation/hooks/config-protection.sh`: blocks edits to lint/format config files (`.editorconfig`, `detekt.yml`, `.detekt.yml`, `checkstyle.xml`) while an SDLC run is active (unsealed checkpoint dir), unless the run's own `_brief.md` names the tool.
- Lands in `android-foundation`, not core `sdlc` — "what is a lint config" is stack-specific knowledge, same reasoning as the existing `kotlin-guard.sh`/`format-on-stop.sh`.
- ADR-0033 records the decision, including a deliberately-accepted risk: the bypass check is a substring match against the brief, so a brief mentioning "checkstyle" for an unrelated reason could false-allow an edit. Accepted because the failure mode is an unwanted *allow* (still caught by normal code review), not a wrongful *block* (which would hard-stop unrelated work) — the asymmetry that makes this an acceptable trade for the pipeline-guardrail case this hook targets.
