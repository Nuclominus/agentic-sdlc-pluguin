# PR #244 — agent handoff contracts — mandatory handoff file, review/test base prompts, AC traceability, per-round mandatory skills

> `fix` · merged 2026-10-28 · by @Nuclominus

## Summary

Hardens the prompt contracts between the orchestrator and its phase agents. Fixes #241, #242 and
#243, all found in the After Action Review of three real Android runs on sdlc 3.2.2.

- **Mandatory skills are a pre-handoff gate on every round (#243).** `developer.md` and
  `reviewer.md` now carry a hard rule: each MANDATORY skill whose moment falls in the current pass
  runs in THIS dispatch. A review-loop or remediation round never inherits round 1's invocation.
  A skill the role cannot invoke goes under `BLOCKERS`, and a review round that reports one is
  not an approval.
- **Tester AC traceability (#242).** The tester builds an AC → test-method table from the BA spec:
  every AC the in-pipeline test task can exercise is covered, or waived with a reason. The
  deliverable gains an `AC traceability` section, and the compact summary an `AC:` totals line.
- **Handoff file is mandatory; review/test base prompts (#241).**
  - The compact handoff contract (stable prefix) states that `detailed_output_path` is a pipeline
    artifact, so writing it overrides the generic "no report .md files" guidance three agents had
    cited to refuse it.
  - `review` and `test` get base prompts. Both point at the agent's own "Return value" block
    rather than carrying a second copy of the machine contract.
- **Orchestrator wiring (from the PR's own review):**
  - New Step 3d-2b reads every phase's `BLOCKERS` line into `phases[].blockers`, a new
    checkpoint-schema field.
  - 3d-2 now records the 3-attempt cap for the `test` phase too.
  - A loop phase learns its round from a per-call `loop_round: N/max` line.
  - The documentation phase reads every prior phase output.
