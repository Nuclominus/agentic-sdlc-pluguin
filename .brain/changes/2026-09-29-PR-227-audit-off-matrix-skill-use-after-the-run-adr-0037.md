# PR #227 — audit off-matrix skill use after the run (ADR-0037)

> `feat` · merged 2026-09-29 · by @Nuclominus

## Summary

PR 4 of 5: off-matrix skill use is audited after the run and never blocked. Claude Code has no
per-subagent skill ACL, so the matrix only decides what each role is *told* to use. This PR
measures what each role actually used.

- **Seal stage** in `run/finish.mjs` (Step 5b). It is fail-open, so an error becomes a WARN and
  never a lost seal.
  - It resolves the static matrix itself (`resolveSkillScope`, read-only), for the stack the run
    used (`telemetry.stack`), not for whatever detection picks now.
  - It reads each phase's own subagent transcript.
  - It judges every catalog `Skill` call as `in_scope`, `off_role` or `unassigned`
    (`usage/skill-scope.mjs`).
  - It writes `skill_scope` and `skill_scope_audit` into `_telemetry.json`, and prints an advisory
    WARN on a leak.
- **Compliance contract `3b-1a-skill-scope`** uses a new `requires: agent_skill_scope` and a new
  cardinality, `every-skill-call`.
  - It scores in-scope calls over catalog calls, judged against the matrix the run recorded, with
    the same shipped `auditSkillScope` as the seal.
  - A run with no recorded matrix scores `n/a` (`no-skill-scope`), never a pass.
- **AAR:** `metrics.mjs` exposes `skill_scope`, where `null` means no audit ran, not a clean run.
  `gather.md` and the analyst turn each off-role or unassigned call into a **scope-leak** finding
  with two remedies:
  - tighten the role's `when`, when the agent strayed;
  - re-triage the row in the skill set, when the matrix was wrong.
