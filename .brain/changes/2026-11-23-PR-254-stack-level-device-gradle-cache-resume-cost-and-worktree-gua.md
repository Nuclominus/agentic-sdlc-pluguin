# PR #254 — stack-level device, Gradle-cache, resume-cost and worktree-guard rules

> `feat` · merged 2026-11-23 · by @Nuclominus

## Summary

Four rules that phase agents kept relearning from per-project memory now ship in the plugins. Two
are Android stack rules delivered through `role_expertise` (device interaction via the `android`
CLI, and a stale-Gradle-cache re-run before blaming a failure on pre-existing breakage). Two are
orchestrator rules in `pipeline-orchestrator/SKILL.md` (a cost ceiling on re-entering an agent that
already returned, and a guard mode for runs started from a `.claude/worktrees/<name>` checkout).
The move follows the ADR-0021 split: platform knowledge lives in the foundation's expertise, not in
the orchestrator's brief, so it reaches on-demand agents too.

## What changed

**android-foundation**
- **Devices go through the `android` CLI when it is on PATH.** `rules/workflow.md` (`qa`,
  `debugging`), the `android-e2e` / `android-debugging` skills and the qa-engineer / debugger
  invariants name the `android-cli` skill: `info`, `install --device … --install-options=-r,-d`,
  `run`, `layout --pretty`, `screen capture`. Agents read `references/interact.md` before the first
  device command; a `-d` downgrade install is followed by `pm clear`. `adb` keeps what the CLI has no
  command for (`pm clear`, `shell input`, `am start`, Logcat, heap dumps) and is the full fallback
  without the binary. Maestro stays the flow runner.
- **Stale Gradle cache** (`rules/snippets/gradle-commands.md`). Before a lint / ktlint / test failure
  is recorded as pre-existing, re-run with `--rerun-tasks --no-build-cache` — `--rerun` only re-runs
  the reporting task, and cached UP-TO-DATE outputs can carry absolute paths from another checkout.

**sdlc orchestrator**
- **Re-entry cost limits (3c-crash).** Recovery stays resume-first. An agent that already returned
  may be reworked via `SendMessage` at most twice, only while its carried prefix is under ~100k
  tokens, and never across a human approval gate; otherwise a fresh agent starts from the plan and
  phase report. A "request changes" on the development plan always re-plans with a fresh agent.
- **Worktree guard mode (Step 2 item 2a, fresh and `--resume`).** Triggers when `docs/plans`
  resolves outside the worktree. The orchestrator writes its own `docs/plans` files via heredoc,
  runs stack commands verbatim (a refusal is a FAIL), and writes the deliverable for Bash-less agents
  (business-analyst, security-analyst) from their `=== DELIVERABLE ===` block. Every phase trailer
  and the session-recorder get a `handoff_write_workaround:` block; the final summary says where to
  commit.

`dist/antigravity` was regenerated in the same PR (ADR-0029 emit parity).
