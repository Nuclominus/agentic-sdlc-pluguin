# PR #270 — accept --brief <path> and a quoted brief path

> `fix` · merged 2026-11-28 · by @Nuclominus

## Summary

`/sdlc:start --brief` read only `--brief=<path>` and halted on `--brief <path>`. On the first sdlc
3.4.1 run in parlor-android (`blank-photo-threshold-fix`, the H5-D2 run 6), the session that
composed the command wrote the space form. The orchestrator then spent a failed resolve and a
retry inside the start window — one of the three calls that kept that run at 6 API calls instead
of the expected 3. The resolver now reads `--brief <path>`, `--brief='<path>'` and
`--brief "<path>"` the same way as `--brief=<path>`.

**Why the narrow fix.** Three wider options were considered and rejected in-session:
- **A general shell tokenizer** would be a second argument parser with its own quote semantics,
  beside the regex-parsed `--workflow=`, `--stack=` and `--resume=`.
- **Normalizing the frontmatter slug** would silently rename the run directory, so a later
  `--resume=<slug from the brief>` would miss it. The strict error is the guard, and `/sdlc:brief`
  always writes a valid slug.
- **A new prose instruction** cannot help, because the command was composed by a session that
  never reads the plugin's text. Only the resolver sees every caller.

## What changed

- **`briefToken`** (`plugins/sdlc/tools/resolve/brief.mjs`). The flag is still recognised only
  when bare: it is located in the quote-blanked text, so a quoted mention stays description. Its
  value may be `=`-joined or the next token, optionally in one pair of quotes. The whole
  flag-plus-path span is removed before the description check and replaced in `briefArgs`, so the
  path never reaches recipe matching. An empty value, a following flag or an unclosed quote still
  halts, now with `--brief: give a path — --brief=<path> or --brief <path>`.
- **Review fix.** `briefArgs` now inserts a space when a flag is glued to the closing quote.
  Without it, `--brief="x.md"--dry-run` became `"T"--dry-run`, the flag was lost, and a preview
  would have started a real run.
- `commands/start.md` notes the accepted forms; a `### Fixed` CHANGELOG entry sits under
  `[Unreleased]`; `dist/antigravity` was regenerated. The `sdlc` version is not bumped here — that
  is owed before the next `/release`.
- Tests: the space and quoted forms resolve identically to `=`, both in-process and end to end
  (same `plan.brief` and recipe); the bad values halt; the glued-flag case; and the existing
  quoted-mention cases unchanged. A separate read-only review session ran two rounds, ending in
  "No remarks on the code".
