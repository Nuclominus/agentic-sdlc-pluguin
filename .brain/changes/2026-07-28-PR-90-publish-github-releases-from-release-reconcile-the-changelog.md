# PR #90 — publish GitHub releases from /release; reconcile the changelog

> `chore` · merged 2026-07-28 · by @Nuclominus

## Summary

`/release` stopped at the tag. `v1.10.0`, `v1.11.0` and `v1.11.1` all shipped to the stable `@release` channel with **no GitHub release** — `v1.9.1` still reads as Latest on the releases page. `CHANGELOG.md` had drifted the same way: one `## [Unreleased]` section covering a single PR (#70) while three marketplace versions had already been cut.

## Changed areas

Repo-level only — no plugin under `plugins/` touched, so nothing in the shipped payload changed.

- **`.claude/commands/release.md`** (maintainer command, deliberately not shipped in any plugin).
  Three new steps: roadmap-board refresh (3a, runs `roadmap/generate.mjs` in the release worktree),
  changelog promotion (3b, `## [Unreleased]` → `## [X.Y.Z] — YYYY-MM-DD` with a fresh empty
  Unreleased above), and the GitHub release itself (7, `gh release create --verify-tag` with the
  promoted section as the body).
- **`CHANGELOG.md`** — `[1.10.0]`, `[1.11.0]` and `[1.11.1]` reconstructed from the vault change
  notes for #58–#88; the stale `[Unreleased]` body (the #70 plugin-paths fix) filed under `[1.10.0]`
  where it actually shipped.

## Decisions & rationale

No ADR — this is process plumbing, not an architectural decision. The reasoning worth keeping:

- **The release is not the tag.** `v1.10.0`–`v1.11.1` all reached the stable `@release` channel
  while the releases page still showed `v1.9.1` as Latest. A cut that stops at the tag leaves every
  downstream reader looking at a version three releases stale, so publishing moved inside the
  command rather than staying a remembered manual step — the same reasoning that later produced
  [[decisions/ADR-0012-unpriced-runs-must-not-render-a-cap-verdict]]: a step a human or model must
  *remember* is a step that eventually does not happen.
- **Fail before any ref moves.** `gh auth status` and the already-published `gh release view` check
  moved into preflight, so an unauthenticated or repeated run stops before the develop bump, the
  `release` fast-forward or the tag.
- **`--verify-tag`** so a half-applied release cannot leave a dangling GitHub release pointing at a
  tag that was never pushed.
- **The vault stays the SSOT.** Step 3a regenerates `roadmap/index.html` only; `.brain/planning/roadmap.md`
  is hand-curated and explicitly off-limits to the command.
- **Resume hole closed.** Re-running with the same explicit `X.Y.Z` used to fail the
  "strictly greater than current" guard once the bump had landed; equality now reads as a resume and
  picks up at whichever of steps 6–7 did not run.
- Staging is per-path, never `git add -A`.
