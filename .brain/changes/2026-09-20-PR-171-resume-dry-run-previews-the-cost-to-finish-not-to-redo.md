# PR #171 — --resume --dry-run previews the cost to finish, not to redo

> `fix` · merged 2026-09-20 · by @Nuclominus

## Summary

Closes #168. `commands/start.md` promised "Combine with `--dry-run` to preview what would be
skipped without dispatching anything". It previewed a full run: every phase priced as if it were
about to be dispatched, no `⏩` rows, and a cap verdict for work already done — on a run resumed
near the end, `EXCEEDS` against a remaining cost of nearly zero.

The rendering had been complete since the day it was written. `caps.mjs` zeroes a resumed row,
excludes it from the loop/heal/gate arithmetic, renders `⏩ … skipped (resumed from checkpoint)`,
and emits `resumed`/`reenter_at` headlessly. `plan.mjs` never passed `resumedDone`, so every one of
those branches was unreachable from the CLI — and untested through `resolvePlan`, which is how it
stayed that way. `resolveResume` now locates the workspace, reads the checkpoints and supplies the
set; a four-checkpoint run drops from `~$4.38` to `~$0.32`, re-entering at `remediation`.

## Decisions & rationale

- **"Done" is not redefined.** `loadCheckpoints` + `doneUnitIds` come from `tools/run/reentry.mjs`,
  the module `--resume` and the H6 seal gate already share and that the orchestrator's resume
  contract names as the tested source of truth. `resolveWorkspace` was the wrong entry point only
  because it demands the `_run.json` a not-yet-started run has not written. This is
  [[decisions/ADR-0019-the-run-start-is-one-command]]'s "no second implementation" applied, not a
  new decision — hence no ADR.
- **The slug is reported, not guessed around.** Step 2 derives it from `$ARGUMENTS` in prose, so a
  model's slug and the resolver's can differ. A bare `--resume` that finds no checkpoint directory
  WARNs and prices a full run rather than presenting one as a resume; `--resume=<slug>` is exact.
- **Checked and deliberately not changed:** the issue suspected the real-run path carried the same
  inflated cap basis. It does not — `estimate()` is called only under `--dry-run`, and `cost_cap`
  is the recipe's declared limit rather than a computed basis.

### What the review of this PR caught

Worth recording, because four of the five were invisible to the PR's own verification:

- **The fix was unreachable from `/sdlc:start`.** Step 1 said "Strip the flag from the description"
  for `--resume`, and Step 2 passed `$ARGUMENTS` "unchanged apart from `--resume`" — so Step 0's
  `plan --json "$ARGUMENTS"` never saw it. The paragraph one above already forbids exactly this for
  `--stack=NAME`. Every check in the PR called `cli.mjs` or `resolvePlan` directly, never the
  command layer, which is how a command-layer defect survives a green suite. **The general lesson:
  a fix whose entry point is a prompt file is not verified by exercising the code it calls.**
- A `--resume` that resumed nothing still printed `⏭ Resume: … 0 of 6 complete` and emitted
  `{"resumed": true}` beside the *full* estimate: the output was gated on the flag rather than on
  what was actually resumed.
- A bare `{phase}.json` zeroed every aspect of an aspect-aware phase, while `reentry.mjs` requires
  each `{phase}-{aspect}`. That under-priced a `development` fan-out (×5.4, the dominant term) —
  and two test fixtures had encoded the divergence as expected behaviour.
- `--mode tree "Add dark mode"` derived the slug `tree-add-dark-mode`; `--resume=` with an empty
  value was silently inert, the exact invisible failure the new comments set out to prevent.
