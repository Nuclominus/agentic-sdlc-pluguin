# PR #56 — overhead window from machine anchor, not LLM timestamps (1.9.1)

> `fix` · merged 2026-07-08 · by @Nuclominus

## Summary

`orchestration_overhead.main_loop` is priced by filtering the orchestrator's turns to a time window read from telemetry `started_at`/`completed_at` — **ISO strings the LLM orchestrator authors in Step 5**. On run `cit-478-batch-editor-animations` it wrote a start of `00:14:19Z` where the machine anchor (`.checkpoint/_started_at` epoch) and the real transcript turns were at `14:54:19Z`: right *duration* (2776s, so `completed_at` stayed self-consistent), absolute start off ~14h.

**Impact.** `priceMainLoop` then filtered *every* one of the ~34 `claude-opus-4-8` orchestrator turns out of that window, so `main_loop` collapsed to `{turns: 0, cost_usd: null}` and the run's largest cost bucket read as **$0** — reported **$8.15** against a true **$13.22**. Per-phase costs use no window, so they looked fine and the loss was silent.

**Fix.** `overheadWindow()` now sources the window from the machine-written `.checkpoint/_started_at`
epoch + `wall_clock_seconds`, falling back to the telemetry ISO only when no anchor exists (older
runs). Defense-in-depth: if a window still excludes every main-loop turn while the transcript has
some, it reprices unbounded and returns `overhead_window_fallback`, and `cli.mjs` prints a WARN — a
zeroed overhead can never be silent again. TDD: two failing tests first (anchor overrides a wrong
window; fallback flags a zeroed window), then the fix; full `sdlc-lint` suite green (106).
