# PR #137 — Refresh the model registry to Fable 5.1 and current per-MTok pricing

> `other` · merged 2026-09-04 · by @Nuclominus

## Summary

A data refresh of the model registry, plus the first repair of the shape that let the data drift
silently. `plugins/sdlc/config/models.json` is the single source of truth for `tag → model_id` and
per-MTok pricing (#16, #17); checked against Anthropic's pricing, models-overview and deprecations
pages on 2026-09-04 it had drifted in three ways.

**The `fable` tier pointed at the legacy model.** Sessions are served by Claude Fable 5.1
(`claude-fable-5-1`), but the tier resolved to `claude-fable-5`. That is the same failure as the
July `opus` repoint (`f0a5b9e`): a served id with no registry entry prices every phase on that tier
to `cost_usd: null`, which enters the cap gate as `$0` while `cap_status` reads `within`. Fable 5.1
also prices cache reads at **0.025×** input (`$0.25/MTok`) rather than the standard 0.1×, so the
tier's `cached_input` moved `1.00 → 0.25`; input/output stay `$10/$50`. `mythos` moved to
`claude-mythos-5-1` on the same rate.

**Sonnet 5's intro-pricing note was stale.** `$2 / $0.20 / $10` became Anthropic's standard price;
the scheduled 2026-09-01 rise to `$3/$15` was cancelled. The `pricing.note` that flagged the expiry
is gone.

**Active models had no entry.** Pin-only tags keep every active id priceable: `fable-5`,
`mythos-5` (the superseded generations at their old rates), `opus-4-5`, `sonnet-4-5`. Convention,
now uniform: the **bare tag is the current generation, the suffixed tag is the superseded pin**.
No tier was added, so `pipeline_tiers`, `enforce-agent-model.sh` and both schemas are untouched.

The PR was reviewed in-session before merge (the first use of the new post-PR review rule) and
the review changed it in two ways worth keeping. Pins are keyed on the **bare** id — `lookupPricing`
strips a snapshot date and never adds one, so a dated key (`claude-opus-4-5-20251101`) resolved
the bare alias to `null`, the exact failure the pin was added to prevent. And the usage test's
tier→model map is now *derived* from the registry rather than restated, which on its own guards
nothing (the reviewer proved a typo'd fable id and a `cached_input` of `0` or `99` both stayed
green), so the four tier ids, tag uniqueness and the Fable 5.1 estimate row (`$1.38655`) are pinned
explicitly.

Three review findings were left open as follow-ups because they are pre-existing: end-of-run
enrichment reports an unpriced-model phase as `skipped (no transcript)` and discards the id, which is
why both tier repoints were silent; the `lookupPricing` docstring still calls haiku "the one dated
registry key"; and the orchestrator's `_telemetry.json` example carries hand-maintained model ids
among placeholder fields.
