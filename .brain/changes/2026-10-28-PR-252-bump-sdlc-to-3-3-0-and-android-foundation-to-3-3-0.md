## Summary

Closes the AAR fix series with one consolidated release step. `sdlc` 3.2.2 → 3.3.0 and
`android-foundation` 3.2.0 → 3.3.0, both minor. #244–#247 were built in parallel and deliberately
left versions and `CHANGELOG.md` alone, so the four PRs could not conflict on them. All four were
merged first, each with its brain-sync follow-up (#248–#251).

- **Why minor.** The fixes change visible behaviour:
  - Android gates that used to pass silently now fail.
  - A fresh branch keeps its security phase.
  - There is a new optional `default_variant` key.
  - Telemetry gains `phases[].blockers` and `orchestration_overhead.window`.
- **`CHANGELOG.md` `[Unreleased]`** gains Added / Fixed / Changed sections for the series. It
  separates telemetry fields from resolver plan output (`plan.skip_rules.withheld[]`) and command
  results (`overhead_window_missing`), none of which reach `_telemetry.json`.
- **Version guard (review follow-up).** android-foundation 3.3.0 calls its gate script through
  `${CLAUDE_PLUGIN_ROOT}`, which only the sdlc 3.3.0 resolver binds. `plugin.json` dependencies
  are bare names by policy (ADR-0028), so the requirement lives in the gate commands: each checks
  for the script first. Under an older core, every gate FAILS with `… needs sdlc 3.3.0+ …` instead
  of exiting 127, which the orchestrator would record as a silent SKIP. The commands use `false`,
  not `exit`, because they run in the orchestrator's own shell. `schema.test.mjs` runs every gate
  under an unbound and a bound plugin root.
- The marketplace version (4.3.0) is unchanged; `/release` bumps it when the release is cut.
