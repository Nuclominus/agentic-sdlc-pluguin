# PR #226 — /sdlc:doctor reports skill catalogs (ADR-0036)

> `feat` · merged 2026-09-29 · by @Nuclominus

## Summary

PR 3 of 5: `/sdlc:doctor` now diagnoses skill catalogs such as the Android CLI's agent skills.

- **New read-only verb:** `resolve/cli.mjs deps [--json] [--probe]`. It runs the pipeline's own
  dependency preflight without writing its stamp or enforcing any policy. A missing `block`
  dependency is reported in `would_abort_pipeline` and the verb still exits 0.
- **`resolve/catalogs.mjs`** builds one `skill_catalogs[]` entry per `kind: skill-catalog`
  dependency. Each entry reports:
  - the installed catalog version against the version the matrix was triaged for;
  - the skills needed in this project against those assigned, plus the ones gated off here;
  - each missing skill with the roles it costs, mandatory rows first;
  - each host tool with its path, and its `--version` when `--probe` is passed;
  - stale installed copies, found by a content hash against the CLI's local clone (`catalog_dir`);
  - the same bare id installed in more than one skills folder;
  - catalog skills the matrix has not triaged, and matrix ids the catalog no longer ships;
  - the install, update and alternative-install commands, printed but never run.
- **When the catalog doesn't apply:** if the declaring foundation doesn't detect the project, the
  catalog's entry is a single "not used by this project" line.
- **Doctor skill:** steps 1–2 delegate to the verb instead of re-running the algorithm in prose,
  and the hard-coded `android --version` probe is gone. The JSON gains `skill_catalogs` and drops
  `host.toolchains.android`.
- **Catalog location:** the `android-skills` dependency now declares
  `catalog_dir: $HOME/.android/cli/skills`.
