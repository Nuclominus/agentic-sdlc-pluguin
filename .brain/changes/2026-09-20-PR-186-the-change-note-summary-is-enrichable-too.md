# PR #186 — the change-note Summary is enrichable too

> `docs` · merged 2026-09-20 · by @Nuclominus

## Summary

`.claude/rules/second-brain.md` §4 said to enrich only the prose **below** a change note's auto
Summary. The vault had never worked that way: [[changes/2026-09-20-PR-178-resolve-a-workflow-recipe-named-in-the-request-176]]
carries a three-paragraph written Summary that is the most useful part of the note, and #181
followed the same practice. The rule and the thing it governed contradicted each other.

This resolves it in favour of the practice. Only the **frontmatter** and `changes/_moc-changes.md`
are machine-owned; `render.mjs` seeds the Summary from `firstParagraph(pr.body)`, which is a
starting point rather than a reserved field — and the Summary is what a reader hits first, so it
is usually the part most worth writing.

Two corrections travel with it. The old bullet was believed to be a *durability* argument, and it
was not: `sync --pr <n>` regenerates the whole note, Summary and every section below it, so
nothing hand-written survives a re-run either way. The real constraint is **ordering** — run the
tool, then enrich. And because the Summary is copied verbatim from the PR body, a **wikilink in a
PR description is vault content**: in #183's description, a link to
[[decisions/ADR-0013-agent-memory-mirrors-into-the-vault]] written in bare-title shorthand landed
in the vault unresolvable and failed `check`, blocking #184's CI. (`check` scans raw markdown, so
a broken wikilink cannot even be *quoted* inside the vault — this paragraph originally tripped the
rule it describes.)

This note's own Summary is the first written under the amended rule.

## Changed areas

- _Repo-level change (no plugin under `plugins/` touched)._
- `.claude/rules/second-brain.md` §4 — one bullet becomes three: the Summary is enrichable;
  enrich *after* the tool runs, never before; a wikilink in a PR description is vault content.
- `tools/brain-sync/lib/render.mjs` — the generated footer now states the amended rule, so new
  notes stop instructing their reader in the superseded one. Existing notes keep the footer they
  were generated with: it is machine-owned, and rewriting every note to correct a sentence is
  exactly the hand-editing the rule forbids.

## Decisions & rationale

- No ADR: this corrects a rule that misdescribed established practice. There was no decision to
  make beyond which of the two to believe, and the vault had already answered it in every note
  written since.
- **Which way to resolve it was the only real question.** #185 took the other route — restructure
  the #181 note so its reasoning sat below a machine-generated Summary — and was closed
  unmerged. It was mechanically correct and made the vault worse: it moved the best prose out of
  the position a reader reaches first, to satisfy a sentence that no note had obeyed.
- Where a rule and the artefact it governs disagree, **check which one has been paying its way.**
  Here the artefact had; the rule was a stated intention that nothing enforced and nothing
  followed.
- The wikilink bullet is a different lesson in the same section, added because it broke CI in the
  session that found the contradiction (#183 → #184). Recorded where it will be read, rather than
  in a note about the PR that tripped it.
