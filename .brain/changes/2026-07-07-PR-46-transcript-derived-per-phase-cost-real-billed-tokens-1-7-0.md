# PR #46 — transcript-derived per-phase cost + real billed tokens (1.7.0)

> `feat` · merged 2026-07-07 · by @Nuclominus

## Summary

Reported against run `change-matches-filter-logic-gender`: the HTML report + `_telemetry.json` had
**no `cost_usd`** and showed **0 tokens** per phase. Two independent causes: `cost_usd: null` was
ADR-0004 *by design* (the Claude Code Agent envelope exposes only an aggregate
`subagent_tokens` — no input/output/cache split — so a phase could not be priced from it), while the
0-token display was a `report`/`rollup` oversight. Model overrides (`model.local.json`) were ruled
out.

Fix — **price each phase from its subagent transcript instead of the envelope.** New dependency-free
tool `plugins/sdlc/tools/usage/` (`enrich <run-dir> [--session <transcript>]`) reads each phase's
`~/.claude/projects/<cwd>/<session>/subagents/agent-<id>.jsonl`, sums the real
`input`/`output`/`cache-read`/`cache-write` split, prices it against the model registry, and rewrites
`_telemetry.json` with real per-phase `cost_usd`, `billed_tokens`, `cache_creation_tokens`
(`usage_source: "transcript"`), real `total_*` aggregates + `cache_hit_ratio`, and an
`orchestration_overhead` block (orchestrator main-loop bounded to the run window + nested subagents).
`config/models.json` gains `cache_write_multipliers` (5m 1.25×, 1h 2.0×) so prompt-cache *creation*
is priced relative to the input rate; cache *reads* stay at `cached_input` (0.1×). The
orchestrator (Step 3d-1 records `agent_id`, Step 5b runs `enrich` before rendering) wires it forward;
the reported run was backfilled. Report + AAR metrics now render the real billed split.
