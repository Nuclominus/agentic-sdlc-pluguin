## Decisions & rationale

No ADR — this schedules work rather than deciding a design; the ADRs land per phase as each one is
built.

- The premise is that **prose read by a model is a probabilistic instruction**: better wording
  raises compliance odds but never reaches 1. So the track moves load-bearing steps *out of* prose
  (H2 collapse into single commands, H3 the machine-value invariant, H4 deterministic control flow,
  H6 a `Stop` hook) rather than wording `SKILL.md` more firmly.
- **H1 (transcript compliance auditor) goes first because it is diagnostic.** We cannot currently
  tell whether this run was an outlier or whether the orchestrator routinely skips part of its own
  procedure. H4 — the expensive rewrite — is explicitly gated on H1's numbers, so scope is decided
  by data rather than by one incident.
- **H1 displaces E8** as the highest-ROI next step: a cost optimisation is worth less while the cost
  record itself is unreliable.
- The ceiling is stated in the spec rather than left implied: the guarantee extends exactly as far
  as the part of the procedure a machine can perform or verify. Judgement steps — an honest summary,
  the right ADR, noticing the fail-open defect the reviewer missed in that same run — stay
  probabilistic and get detection, not prevention.
- Generalises [[decisions/ADR-0008-read-discipline-contract]] and the "machine contracts cannot live
  in prose" finding from the G1 validation runs; the immediate trigger is
  [[decisions/ADR-0012-unpriced-runs-must-not-render-a-cap-verdict]].
