# PR #135 — Separate development and release logging, and gate it at publish time

> `other` · merged 2026-09-04 · by @Nuclominus

## Summary

Reverses the premise of `android-foundation/rules/logging.md` and then builds the check that the
old version never had.

The rule shipped as "Logging Hygiene", and its premise was that a log statement is **not code**:
logs were "a temporary debugging aid, not a feature", and the operative section was a pre-Done
cleanup sweep — diff the branch, delete every `Logger.` / `Log.` / `println(` / `printStackTrace(`
line added during the session, re-run `ktlintCheck`. That premise makes tracing disposable, pushes
`if (isDebugBuild)` guards into business logic, and is redundant where it actually bites: the
forbidden constructs were already blocked mechanically by `hooks/validate-kotlin.sh` and
`rules/snippets/non-negotiable.md`. What the rule uniquely owned — "remove the rest before Done" —
was prose with no check behind it.

The rule is now organised around **which artifact a log line is compiled into**: a
`Development<Type>` decorator bound by DI in the debug source set (preferred), a lazy runtime
severity gate where there is no seam to decorate (baseline), and a build-flag level set once at a
third-party component's configuration point (the narrow exception). Decorators carry logging and no
behaviour; substitution keys on the build-type axis, never the flavor axis.

The second half of the PR closes the enforcement hole. `kotlin-guard.sh` is
`PostToolUse(Edit|Write)`, so it only ever sees files edited through those tools — a hand edit, a
`sed` in a Bash call, a merge, a rebase or a cherry-pick reached the commit unchecked. The new
`hooks/git-guard.sh` (`PreToolUse(Bash)`) gates `git commit`, `git push` and `gh pr create`,
re-scanning the staged diff or the branch's commits over its base;
`hooks/validate-logging.sh` is the per-file checker behind it, shaped like `validate-kotlin.sh`.

It **reports and blocks; it never edits code.** Auto-cleaning was requested and deliberately not
built — under ADR-0020 a log line is not something to delete, and the correct fix for a misplaced
trace is a refactor no regex can perform.
