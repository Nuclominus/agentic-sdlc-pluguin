# PR #82 — make the cost cap work — in-run pricing + caps sized against measured cost

> `fix` · merged 2026-07-28 · by @Nuclominus

## Summary

The `caps.max_total_cost_usd` gate (Step 3d-cap) has **never been able to fire on this harness** — not a blind spot in an edge case, dead code on every run.

The gate's only input was Step 3d-1's pricing of the **Agent result envelope**, which on this
harness exposes a single aggregate `subagent_tokens` count with no input/output/cache split
([[decisions/ADR-0004-aggregate-token-telemetry-crash-recovery]]). A phase cannot be priced from
that, so 3d-1 correctly wrote `cost_usd: null` — and 3d-cap counts a `null`-priced phase as `$0`.
Since the aggregate shape is the *ordinary* envelope here, every phase contributed `$0`,
`running_cost_usd` stayed at `0` for the whole run, and `running_cost_usd > cost_cap` was
unreachable at any cap value.

Found on the Android run `flutter-to-native-migration-plan`: cap `$0.75`, actual phase spend
`$3.37`, no pause, `cap_status: "within"` written into telemetry. Re-pricing phase 1's transcript in
isolation gives `$2.97` — from a file whose last write *preceded* phase 2's dispatch. The number
that should have tripped the gate was already on disk, unread.

## Decisions & rationale

- Implements [[decisions/ADR-0011-in-run-transcript-pricing-for-the-cost-cap]], which supersedes the
  cost-*control* half of what [[decisions/ADR-0005-transcript-derived-cost]] left open: ADR-0005 had
  already established that the authoritative price lives in each subagent's transcript, but wired
  the read into Step 5b — *after* the last phase. Cost accounting became accurate while cost control
  stayed broken, and nothing made the contradiction visible.
- **The reconciliation lives in the tool, not in `SKILL.md` prose.** A rule the orchestrator is
  merely told to follow is one it can paraphrase away — the same reasoning that put the abort
  contract in `_telemetry.json` rather than a printed marker line (#77).
- **An unknown cost must never reach a gate as a measured `$0`.** `resolved: false` always pairs
  with `cost_usd: null`. Same failure shape as
  [[decisions/ADR-0007-overhead-window-authoritative-anchor]], where a wrong window silently zeroed
  the largest cost bucket instead of admitting it did not know.
- **The caps themselves were the second bug.** They were derived from the 1d-1 dry-run heuristic,
  which prices a *single API call*; a phase is a multi-turn agent loop (median 12–18 turns, each
  re-reading its prefix), so the heuristic runs 6–10× low and every cap sat below its own recipe's
  median run. Invisible while the gate was dead — and each would have halted an ordinary run the
  moment it started working. Re-derived from 56 transcript-priced phases across 10 real runs as
  `Σ(per-phase p90) × 1.2`. A cap below the median run is not a budget; it is a tripwire that fires
  every time and trains people to click through it.
- **8 of 11 recipes had no cap at all** — including `default`, what runs when nothing else matches.
  An absent cap is not "generous": it makes `CONTEXT.cost_cap` null and skips the gate entirely. All
  11 are now capped, with two lint tests preventing regression.
