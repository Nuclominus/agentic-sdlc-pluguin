# PR #245 — window nested subagents to their run

> `fix` · merged 2026-10-28 · by @Nuclominus

## Summary

Fixes #240: chained SDLC runs in one Claude Code session billed each other's subagents. The AAR
of three chained Android runs measured +$3.32 and +$5.79 of phantom overhead. A fourth run in the
chain could have reported a cost-cap breach that never happened.

- **Nested subagents are windowed per turn.** `usage/usage.mjs` filters the nested bucket by the
  same machine-anchored run window the main loop already used (`overheadWindow`, ADR-0007).
- **Sibling runs' phase agents are excluded by id** (`knownRunAgentIds` over
  `docs/plans/*/_telemetry.json` and checkpoints). This holds even when no window exists.
- **One window, one fallback.** When the window misses every main-loop turn, the nested bucket
  reprices unbounded with the main loop, instead of silently keeping half the overhead.
- **The record says where its window came from.** `orchestration_overhead.window.source` is
  `anchor`, `telemetry`, `open-ended`, `none` or `unbounded-fallback`. A missing or one-sided
  window sets `overhead_window_missing` and prints a WARN in `enrich` / `finish`. The HTML report
  badges such rows `not run-windowed`.
- **Phase dispatches are attributed to their run.** With `--session`, a `Phase N/M` dispatch whose
  phase name an earlier run reused no longer doubles this run's phase cost, which does feed the
  cap gate.
- Known limit: concurrent `/sdlc:batch` pipelines in one session overlap in time and cannot be
  separated. Re-running `enrich <slug>` reprices a past chained run correctly.
