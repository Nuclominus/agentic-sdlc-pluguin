# PR #246 — an empty Step-0 diff is size-unknown, so it keeps security

> `fix` · merged 2026-10-28 · by @Nuclominus

## Summary

Fixes #239. On a fresh feature branch, Step 0c measures an empty diff, because nothing is written
yet. `lightweight-no-db` read that LOC_TOUCHED=0 as "small" and skipped security on a run that
ended at 28 files, purchase screens included. An empty diff is the normal state of a new run, so
the rule fired on almost every one.

- **The diff measures the change, not the commits.** `computeDiffSignals` diffs the merge base
  against the working tree and counts untracked files. The pipeline's own `.sdlc/` and
  `docs/plans/` paths are excluded.
- **Unknown size is a signal.** An empty diff, binary files or more than 500 untracked files set
  `size_unknown`. `loc_touched` then takes the safe `999999` sentinel, and `loc_measured` keeps
  the lower bound. `locAtLeast()` is the single reader.
- **Size-gated skip-rules are withheld while the size is unknown:** `typo-fix`, `config-only` and
  `lightweight-no-db`. Each withheld rule is recorded in `plan.skip_rules.withheld[]` and printed
  under `🛡️ Skip-rules withheld:`.
- **An unknown size never decides the recipe.** If size would have held back the top-ranked recipe,
  auto-selection abstains and falls through to the stack's full pipeline. The first version let
  the runner-up win, which sent "Fix crash …" to `debug`, a recipe with no security phase. A test
  on the real recipes now guards that case.
- Follow-up, not in this PR: re-evaluate size-gated rules at the `[security ‖ test]` boundary
  against the post-development diff, so a run that turns out small can still drop security. That
  needs `pipeline-orchestrator/SKILL.md`.
