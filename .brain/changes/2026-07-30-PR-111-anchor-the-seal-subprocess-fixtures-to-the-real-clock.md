## Decisions & rationale

**A fixture for a subprocess cannot use an injected clock.** The suite pins everything to a fixed
`ANCHOR` (2026-07-28T11:00Z) and passes `now` into the library calls, which is what makes those
tests deterministic. But three tests spawn the real `run/cli.mjs` and the real `Stop` hook, and a
child process reads `Date.now()` — there is nothing to inject into. Against a fixed anchor those
fixtures age past `findSealable`'s 24h `DEFAULT_MAX_AGE_MS` window and are skipped with reason
`"stale"`, so the assertions held only during the day following `ANCHOR`.

`makePlans` now takes `anchorSecs`; the subprocess tests pass `RECENT()`, an anchor derived from the
real clock that preserves the same 600s start→last-activity gap, so `wall_clock_seconds` stays 600
and nothing else about the fixture shifts. `makeProject` defaults to it, since every one of its
callers spawns the hook.

**The failure mode is the lesson, not the fix.** A stale fixture did not fail as "your fixture
expired" — it failed as `sealed.length` being 0 instead of 1, which reads like a bug in the sealing
logic, on pull requests that touched neither the sealer nor its tests. `develop` sat red from
2026-07-29 and two unrelated PRs (#110, #114) inherited a red baseline that cost real time to
attribute. A time-dependent test that rots silently is worse than one that never existed, because it
spends other people's debugging budget.

The regression guard added here calls `findSealable` with **no** injected `now` and asserts both
directions: a `RECENT()` fixture is sealable, and a fixed-anchor one is exactly what is not. The next
person to pin a subprocess fixture to a constant gets a test that says why, on the same day rather
than the next one. This is the same instinct as [[decisions/ADR-0015-the-machine-value-invariant]] —
do not let a value the machine can compute be restated as a constant that drifts out from under you.
