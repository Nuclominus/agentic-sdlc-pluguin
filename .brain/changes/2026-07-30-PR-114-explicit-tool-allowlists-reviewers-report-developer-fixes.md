## Decisions & rationale

Implements [[decisions/ADR-0018-reviewers-do-not-write-code]]. Three findings are worth keeping
beyond what the ADR records.

**An allowlist that is absent is not a default.** Omitting `tools:` grants the FULL toolset, so ten
of eleven `android-foundation` agents held every tool regardless of what their prompt claimed.
`android-reviewer` declared itself "READ-ONLY … does NOT write code" and could `Edit` anything;
`android-debugger` routed "Writing the fix → `android-developer`" and then, four sections later,
told itself to "Fix root cause". Every prompt said the right thing. Prose does not hold boundaries —
this is the same class of failure as
[[decisions/ADR-0015-the-machine-value-invariant]] and the reason
[[decisions/ADR-0008-read-discipline-contract]] is a contract rather than advice.

**The opposite defect was live at the same time.** `business-analyst` and `document-writer` were
instructed to write their deliverable with no `Write` tool, and **no** agent carried `Skill` even
though the orchestrator injects `Convention skills to consider invoking:` into every phase prompt —
so every mandatory row in `android-foundation/rules/skills.md` had been failing silently. A
restrictive list is not automatically a safe one; it has to be checked against what the phase prompt
actually asks the agent to do.

**Two latent defects surfaced from tracing the resolved DAG, not from review.** Neither would have
failed loudly:

- `3-parallel` step 4 specified only "run 3e validation on each" and never that members run **3d**,
  the step that populates `CONTEXT.{phase}_output`. `security` is a parallel member and the new gate
  reads exactly that field, so the gate would have failed open on *every* run — a full development
  dispatch each time, appearing only as unexplained cost.
- `cycles.mjs` validated `loop.return_to` ordering but had no equivalent for `gate.after`, so a
  backwards gate would pass CI and then also always fail open.

Both share a shape: the failure is silent and reads as cost or as nothing at all, never as an error.
That is the argument for `sdlc-lint agent-tools` and the gate-ordering check existing at all —
[[decisions/ADR-0014-the-run-tail-is-one-command]]'s point that a rule which is not machine-checked
is a rule that is already drifting.

**Deliberate exception.** `analysis.yaml` runs `security` with no `remediation`: it is a read-only
BA+security assessment that ships no code, so there is nothing to remediate. The lint encodes the
rule and its exception together, so the exception cannot quietly become the norm.
