# PR #88 — recalibrate the dry-run estimate — it was wrong in shape, not scale

> `fix` · merged 2026-07-28 · by @Nuclominus

## Summary

Closes the last item from the #82 / #86 cost-cap work: the Step 1d-1 `--dry-run` preview still under-reported by 6–10×.

The preview modelled one dispatch as a **single API call** — 35k input, 60% cached, 3k output —
pricing an `opus` row at `$0.16`. A phase is not one call: it is a multi-turn agent loop, and every
turn re-reads the whole accumulated prefix. Measured across 56 transcript-priced phases from 10 real
runs, the real shape is close to the inverse of what was assumed:

| tier | uncached input | cache_read | cache_write | output | median cost |
|---|---|---|---|---|---|
| opus | 29 | 671 703 | 93 178 | 1 125 | $0.95 |
| sonnet | 24 | 724 325 | 72 826 | 1 228 | $0.38 |
| haiku | 194 | 818 723 | 50 928 | 31 | $0.15 |

Uncached input is negligible; **cache reads dominate the bill and were not modelled at all**. That
is the whole 6–10× gap — and why caps derived from this estimate sat below their own median run and
were breached the moment the gate began working (#82).

## Decisions & rationale

No new ADR: this corrects the inputs to an existing mechanism rather than changing how the system is
built. It does complete the arc of
[[decisions/ADR-0011-in-run-transcript-pricing-for-the-cost-cap]] — that ADR fixed what the *gate*
spends, this fixes what the *preview* predicts, so both now derive from the same measurements
instead of contradicting each other.

- **Wrong in shape, not scale.** A flat correction factor would have been the wrong fix: the old
  model's error was structural (it had no term for the cost that dominates), so it was replaced with
  the real four-way split.
- **Priced with the same formula as actual cost** (`priceUsage`, cache-write multipliers included).
  An estimate and an actual now differ only in their token counts, never in how those tokens are
  valued — the previous divergence let a preview and a bill disagree for reasons no reader could
  attribute.
- **Baselines live in the model registry**, beside pricing, following the same SSOT rule that keeps
  model IDs and rates in one place. A second copy in `SKILL.md` prose would have drifted at the
  first retune, so the skill now reads them rather than restating them.
- **`development` ×1.6 → ×5.4.** The old value was reasoned from pass *count* (plan ≈ 0.6 +
  implement ≈ 1.0) — the wrong axis. The second pass is not what makes development expensive: the
  phase runs far longer and each turn re-reads a prefix that has itself grown (median `cache_read`
  4.8M against 725k for an ordinary sonnet phase). Counting passes cannot predict that; only
  measurement can.
- **Caps deliberately NOT re-derived from the corrected estimate.** An estimate predicts a typical
  run; a cap must clear the tail. Caps stay on measured p90 — the two now agree in *method*, which
  was the goal, rather than in value.
- A test pins the **shape** (`cache_read` must dominate uncached input), not just the numbers, so a
  future retune cannot silently revert to the broken model and have its figures appear to agree by
  coincidence.
