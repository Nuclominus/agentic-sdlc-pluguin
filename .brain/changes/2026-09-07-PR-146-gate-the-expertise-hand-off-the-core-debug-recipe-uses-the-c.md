## The gate, and why it needed a new cardinality

ADR-0021 moved platform expertise out of the agent bodies — where it was structurally guaranteed,
an agent's body being its system prompt — into a block the orchestrator pastes at 3b-1a. The
[[planning/i1-agents-in-core|validation run]] measured the price: of the ten dispatches going to
agents the resolver had rendered a block for, **nine received it**. The `documentation` phase got
neither block, and the run finished green.

The denominator was the whole problem. `once-per-phase` cannot express this: a review loop
dispatches `development` three times, so counting matches against the phase count reads 9 ≥ 7 and
**passes the very run that missed one**. So `every-dispatch` scopes to
`dispatch_scope: telemetry.expertise_block_agents` — the agents *this run dispatches* that hold a
block — and nine of ten is nine of ten. The list is stated by the plan under the same key, so the
orchestrator copies rather than recounts ([[decisions/ADR-0015-the-machine-value-invariant]]).

Not gated here, for a structural reason worth recording: **mandatory-skill invocation**.
`resolveRunSessions` walks from a subagent transcript *up* to its parent session, so the auditor
reads the main transcript only, while a subagent's own `Skill` calls live in
`subagents/agent-*.jsonl`. Gating that needs a second transcript tier and a way to recover a
dispatch's mandated set from its prompt — its own piece of work.

## What the review caught

Six findings, all confirmed before acting. The important one is that the gate, as first written,
was a **generator of false failures** — the exact fault it exists to prevent. `prompt_blocks`
deliberately covers the on-demand roster so `expertise --role` can serve it, but 3b-1a pastes
nothing for those agents. Since the auditor reads the whole session, a `/sdlc:aar` after a
`/sdlc:start` put `aar-analyst` into `expected` where it could never match, reporting a fully
compliant run as `partial 9/10`. Scope is now computed from the resolved workflow's own phases.

Two more of the same family: `every-dispatch` paired with a non-`agent_prompt` `requires` parsed
cleanly and then threw out of `new RegExp` mid-audit, breaking `auditRun`'s documented "never
throws" invariant and taking the whole corpus down; and the session-wide fact stream let a
neighbouring run's dispatch enter `expected`, so the audit is now bounded by the run's own
`started_at`/`completed_at` (falling back to the full stream on a half-open window, which would
otherwise drop every dispatch and read as a clean `n/a`). The remaining three were docs still
asserting what `debug.yaml` no longer does.

## Decisions & rationale

- No new ADR. This is [[decisions/ADR-0021-agents-live-in-the-core-foundations-carry-expertise]]
  paying its own bill: the ADR traded a structural guarantee for a platform-neutral roster, and
  this is the instrument that watches the trade. It applies
  [[decisions/ADR-0015-the-machine-value-invariant]] to the new telemetry field, and belongs to the
  Track H premise that prose read by a model is a probabilistic instruction — so a load-bearing
  step gets measured rather than worded more firmly.
- The core `debug` recipe now runs `debugging → development → qa`. PR-1 bound
  `debugging: debugger` in the core manifest, but the recipe kept the shape it had when vanilla
  shipped no such agent, handing root-cause analysis to `development` — which holds `Edit` — while
  the read-only agent built for the job sat unused ([[decisions/ADR-0018-reviewers-do-not-write-code]]
  is the same principle). Cap re-based on the p90s `android-debug` already uses: $0.52 + $5.41 +
  $1.48 = $7.41, ×1.2 → $9.00.
