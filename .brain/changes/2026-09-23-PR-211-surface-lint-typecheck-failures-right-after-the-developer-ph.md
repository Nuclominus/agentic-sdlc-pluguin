# PR #211 — surface lint/typecheck failures right after the developer phase (android-foundation)

> `feat` · merged 2026-09-23 · by @Nuclominus

## Summary

- New `SubagentStop` hook `plugins/android-foundation/hooks/post-implement-check.sh`: runs
  `ktlint`/`detekt` right after the `developer`/`tester` subagent stops (matched on the
  top-level `.agent_type` field, not `.subagent_type`) and writes the result to a state file,
  `docs/plans/{active_run}/.checkpoint/_post-implement-check.json`
  (`{status, issue_count, tool, at}`), distinguishing "task not found" (`status: "skipped"`)
  from a real lint failure (`status: "fail"`).
- The state file exists because `SubagentStop` stdout does not reach the transcript on this
  platform — confirmed directly against the hooks docs after an earlier assumption to the
  contrary (that plain stdout always surfaces) turned out to be wrong; the hook's PASS/FAIL
  signal would have silently done nothing without this fix.
- **Never blocks** — an unbounded hook-level retry loop is a worse failure mode than a missed
  lint pass, and the platform doesn't let this event block the agent from stopping anyway.
- Wires the signal into the orchestrator's existing `3e` validation step in
  `pipeline-orchestrator/SKILL.md`: the orchestrator reads the state file once and MUST delete
  it immediately after reading (pass, fail, or skipped alike), so a stale result from an earlier
  phase can't re-trigger on a later one.
- ADR-0034 records the decision, including the exit-code-2 behavior note for `SubagentStop`
  that could not be independently re-confirmed against the docs (the hook never uses exit 2,
  so this doesn't affect actual behavior).
