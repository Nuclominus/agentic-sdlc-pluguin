# PR #148 — scope skill triggers to the dispatch — a re-dispatch owes them too

> `fix` · merged 2026-09-07 · by @Nuclominus

## Summary

Two Android runs, a day apart, missed the same thing in the same place. This is the cause and the
fix.

## Changed areas

- [[components/android-foundation]]
- [[components/sdlc]]

## The measurement

| Dispatch | MANDATORY rows | Skills invoked | Production edits |
|---|---|---|---|
| `development (implement)` | 3 | **3** | 24 |
| `development (review fixes)` | 3 | **0** | 7 |

The 2026-09-06 run has the identical shape — the loop round made 5 edits and invoked nothing. Every
other dispatch in both runs complied: BA 3/3, reviewer 2/2, tester 1/1, qa 1/1, document-writer 1/1.
The miss is specific to the **review-loop re-dispatch of `developer`**, and it reproduced.

## The cause — the agent was obeying, not ignoring

Its triggers said `before **the first** Write/Edit of production Kotlin` and `before **implementing**
a Compose screen`. Its own `loop_findings` block said the implementation is *already on disk* and
must **not** be re-implemented. Read literally against that framing the first trigger had already
passed and the second did not apply; only the hand-off trigger still fired, and it went with them.

**This is why it is not the [[planning/h1-compliance-auditor|H1]] "firmer wording" case.** H1
measured emphasis and found it worth about 3%. Here the instruction was not weak — it was *false* on
a re-dispatch, and no amount of "Do not skip" repairs a trigger that correctly says *not now*. The
distinction matters for the next such decision: check whether a mandate is being disregarded or is
simply not firing before reaching for stronger prose.

## Both sides of the contradiction

Fixing only the triggers would have been a guess about which side dominates, so both moved:

- every `when` is scoped to the dispatch — `before your first Write/Edit of production Kotlin in
  THIS dispatch — a review-loop round counts`;
- `sdlc-lint roster` rejects the run-scoped form, with a negative lookahead so `first … in this
  dispatch` passes: the rule bites the scoping, not the word. Test-first, and on its first run
  against the shipped tree it found **three more** of the same shape — `reviewer`, `tester`,
  `debugger` — all re-dispatched by the loop, by heal, or by a repeated phase, none yet measured
  failing;
- the schema's own `when` example *was* the defective phrasing, i.e. the template every foundation
  author copies. It now teaches the per-dispatch form and names the lint;
- the orchestrator states that `loop_findings` narrows a round's **scope** and retires none of the
  role's obligations.

## Not claimed

A fix with a mechanism, not a proven outcome. n=2 for the defect; no run behind the fix yet. What is
guaranteed mechanically is only that a run-scoped trigger cannot ship again — whether the agent now
invokes its skills on a loop round is what the next run measures.
