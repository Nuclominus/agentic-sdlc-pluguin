## Decisions & rationale

- **The fix is two halves, and the first alone would be worse than the bug.** A preview request that
  fires the skill but reaches `plan` without `--dry-run` does not preview anything — it starts the
  pipeline. So Step 0 appends the flag when the request is a preview and the user did not type it.
- **The flag goes INTO `$ARGUMENTS`, not into argv.** Step 1d-2's stop gate is keyed on `$ARGUMENTS`
  containing the flag and the resolver accepts either, so a flag that only reached the resolver
  would print the preview and leave the gate false — preview announced, agents dispatched anyway.
- **The natural-language entry path had to define `$ARGUMENTS` at all.** It is declared (Inputs) only
  as the slash command's argument, yet `task_slug`, `_brief.md`, language detection and the skip-rule
  `arguments_pattern` all read it. Left undefined, an NL preview would have run the resolver on an
  empty string and started a pipeline on an empty brief. Inputs now defines it for that path and
  requires stopping to ask when the request names no change.
- **Triggers require a named change**, stated above both lists, so the negative cases
  (`07-neg-sdlc-question`, `08-neg-trivial-rename`) stay guarded and bare "how much would it cost"
  does not select the orchestrator for whatever else was being discussed.
- No ADR: this is a prompt-surface correction within the boundary
  [[decisions/ADR-0019-the-run-start-is-one-command]] already set — the resolver owns the phases, the
  estimate and the cap verdict; the skill's job was to reach it. Per
  [[decisions/ADR-0015-the-machine-value-invariant]], recalling any of those numbers is not an option,
  which is why the enriched text here states none either.
- The last four points all came from the **code review of this PR**. The bilingual trigger list also
  drew an owner instruction mid-review to romanise it; that change was reverted before landing, so
  the UA line stays Cyrillic and consistent with the agent roster's own `Trigger words — UA:` lists.
