# PR #92 — stop reporting a cap verdict on a run nothing priced

> `fix` · merged 2026-07-28 · by @Nuclominus

## Summary

An observed Android run (`native-chat-engine-s2-thread-list`) finished and rendered a report reading `— · $16.50 cap · within`, with `total_cost_usd: null`, `cost_basis: "subagent_aggregate"` and `cap_gate_blind: true` on every phase.

Re-running enrichment against transcripts that had been on disk the whole time priced that run at
**$15.38 — 93% of its cap**. Nothing had breached; nothing had checked either. The session
transcript shows why: across 42 `Bash` calls, `tools/report/cli.mjs` ran once and
`tools/usage/cli.mjs` **never** — neither the in-run pricing call (3d-1b) nor Step 5b enrichment
fired, including the WARN that was supposed to announce their absence.

A second defect sat behind the first. Step 5b(a) derived `--session` by encoding the *current* cwd,
but the harness files a session under the cwd it **started** in — so any run that moves into a git
worktree (every `/sdlc:batch` task; this one spent 196 of 247 events inside one) resolved to an
unrelated session. Phase costs survived via the projects-root glob, but orchestration overhead was
priced against a stranger's main loop: **$0.55 reported where the truth was $5.21**, output still
reading as a clean enrichment.

## Changed areas

- [[components/sdlc]] — four fixes, all in the cost-record path:
  - `tools/report/report.mjs` — new `capVerified()`; a cap verdict renders only when
    `cost_basis == "transcript"` **and** `total_cost_usd != null`, else `unverified — run unpriced`
    plus a `Cost: unpriced` signal naming the `cap_gate_blind` phases. `renderReportFile` returns
    `cap_unverified` so `tools/report/cli.mjs` can WARN on stderr.
  - `tools/usage/usage.mjs` — `sessionOwnsRun()` / `knownRunAgentIds()`; a `--session` whose
    subagents dir holds none of the run's agents is discarded (`session_mismatch`) and the real
    session recovered by walking back from a resolved phase transcript. A backfill run with no known
    ids still trusts the session it is handed — there the dispatch map is the only source.
  - `tools/report/report.mjs` — QA iterations summed across phases instead of read off a phase
    literally named `qa`; `android-feature` runs the loop as `test`, so a run that spent 2 rendered
    `0` while `tools/aar/metrics.mjs`, which sums, reported 2 off the same file.
  - `tools/usage/usage.mjs` — `reconcileRunWindow()` corrects `started_at` / `completed_at` against
    `.checkpoint/_started_at` (120s tolerance), leaving `wall_clock_seconds` — the anchor's own
    arithmetic — untouched.
- `skills/pipeline-orchestrator/SKILL.md` — Step 5b(a) now anchors the session lookup on a
  dispatched `agent_id` and says to omit `--session` when that fails; 5b(c) states that the
  machine-side guards fire regardless and must not be hand-edited away; 5b(e) documents the window
  reconciliation.
- `docs/COST-AND-MODELS.md` gained a `cap_status` trust paragraph.

## Decisions & rationale

- Implements [[decisions/ADR-0012-unpriced-runs-must-not-render-a-cap-verdict]] — a cost verdict
  must attest to the pricing behind it, and session transcripts are located by agent id, never by
  cwd.
- Guards the record written by [[decisions/ADR-0011-in-run-transcript-pricing-for-the-cost-cap]]:
  that ADR made the cap able to fire, this one stops a *silent* pricing failure from presenting as
  a clean verdict.
- Extends the authority of [[decisions/ADR-0007-overhead-window-authoritative-anchor]] beyond
  pricing: the machine anchor now also corrects the ISO strings the report header, the journal and
  every rollup read.
- `total_cost_usd` alone was rejected as the trust test — an `estimated` / `subagent_aggregate`
  basis carries a number that never went through transcript pricing.
- Deliberately **not** attempted: making the enrich call structurally unskippable. This makes the
  skip loud, not impossible.
