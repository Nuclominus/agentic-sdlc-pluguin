# PR #247 — flavor-aware heal and post-pipeline Gradle gates

> `fix` · merged 2026-10-28 · by @Nuclominus

## Summary

Fixes #238. android-foundation's Gradle gates ran the bare `./gradlew compileDebugKotlin` /
`testDebugUnitTest`. On an `:app` with product flavors those tasks do not exist, and Gradle skipped
the module without a word and exited 0. In three real runs, every heal and post-pipeline gate
reported green with zero `:app:` tasks executed. The lint line ended in `|| true` and could never
fail.

- **Variant-aware gates (android-foundation).** Every Gradle gate calls
  `scripts/gradle-variant-check.sh <compile|test|lint>`.
  - The script names one project-qualified variant task per module, e.g.
    `:app:compileDevDebugKotlin`. Gradle never silently skips a project-qualified task.
  - The variant comes from `default_variant` in `.sdlc/sdlc.local.yaml`, else the unflavored task,
    else the first flavor.
  - The task listing is cached under `.gradle/sdlc-variant-check/`, keyed on a build-file checksum
    and written atomically.
- **No silent pass.**
  - No module with a target task exits 1.
  - A `./gradlew` without its exec bit runs through `sh` with a WARN, instead of returning 127,
    which the orchestrator reads as a skip.
  - Lint violations now FAIL. A build with no linter prints a visible `lint SKIPPED` WARN.
- **Core change (sdlc):** the resolver binds `${CLAUDE_PLUGIN_ROOT}` in manifest command lists to
  the declaring plugin's directory (`bindPluginRoot`). A project override binds it to the primary
  foundation, so it can keep the shipped gate. `default_variant` joins `KNOWN_LOCAL_KEYS`.
