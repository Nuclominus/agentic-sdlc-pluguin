## Summary

An audit of `README.md`, everything under `docs/`, and the two plugin READMEs the docs redirect to,
against the repo as it stands after v2.0.0. Five files were still describing the pre-ADR-0021
topology — in the places a reader lands first.

## What was wrong, and why these places

The pattern is worth recording: the stale text was concentrated in **diagrams, tables and pointers**
— the artefacts that restate a fact rather than link to it. Prose that described *behaviour* had
been kept current through eleven PRs; every drifted item was a second copy of something the code
already states.

- **`docs/WORKFLOW.md`, the Stack Provider diagram** showed `fallback agents (vanilla)` in the core
  beside `11 android-* agents` in the foundation, with the orchestrator dispatching the latter —
  the exact arrangement 2.0.0 removed. Key principle 2 also had a foundation declaring "agents per
  phase", a key `schemas/manifest.schema.json` now rejects on any non-vanilla foundation.
- **`plugins/sdlc/README.md`** said `agents/ (5 fallback agents)` and carried a seven-row table
  under "Fallback agents". The roster is twelve and is not a fallback; `reviewer`, `tester`,
  `debugger`, `devops` and `cicd` were absent. Its directory tree was missing five commands, three
  workflows, `manifest.yaml`, `config/` and `tools/`. This one propagates: the third
  fix here, `docs/COST-AND-MODELS.md`, redirects to it for per-agent tiers, and pointed at
  `android-foundation` for an "Android roster" that no longer exists.
- **`README.md`** described `/sdlc:doctor` as preflight only, omitting the config migration — the
  single action a `1.x` project must take after upgrading, absent from the front page on the day
  2.0.0 shipped.
