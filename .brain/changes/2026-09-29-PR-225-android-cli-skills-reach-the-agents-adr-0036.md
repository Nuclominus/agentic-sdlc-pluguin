# PR #225 — Android CLI skills reach the agents (ADR-0036)

> `feat` · merged 2026-09-29 · by @Nuclominus

## Summary

PR 2 of 5: the Android CLI skill matrix from #224 now reaches the agents. `sdlc` and
`android-foundation` bump to 3.2.0.

- **Resolver** (`plugins/sdlc/tools/resolve/skillsets.mjs`): a manifest's new `skill_sets` key
  turns each assigned matrix row into an ordinary `role_expertise` skill row.
  - The row is a bare id owned via `requires: <set>`, and it appears in the role's prompt block
    and in `expertise --role`.
  - A row whose `applies_if` gate fails is not rendered. For example, a project without CameraX
    never sees `camerax`.
- **Dependency** (`deps.mjs`): a generic `kind: skill-catalog` dependency with `policy: warn`, the
  same level as superpowers. The core stays Android-agnostic.
  - Its required skills and host tools (`requires_tools`) are derived from the matrix.
  - The list is gated for the project and scoped to projects the declaring foundation detects, so
    a Node app with android-foundation installed gets no Android warnings.
  - The preflight stamp is keyed on the catalog's `version_file`.
- **Per-skill downgrade:** an unavailable catalog skill is judged per row, where unavailable means
  not installed or missing its host tool.
  - A mandatory row becomes best-effort, with a WARN.
  - A recommended row is dropped.
- **Removed and updated:** `rules/skills.md` is gone; its CLI command-group bindings became each
  role's `when` text. The SessionStart hook now actually fires on Android projects. It checks for
  a mandated catalog skill (`android init` installs only `android-cli`) and accepts a
  plugin-marketplace install.
- **Review fixes:**
  - gates are memoised per run and skip `build/`, `.gradle/` and `node_modules/`;
  - `skills_used` is gated;
  - the catalog is scoped to the declaring foundation's `detect`;
  - a test covers the plugin-marketplace install route.
