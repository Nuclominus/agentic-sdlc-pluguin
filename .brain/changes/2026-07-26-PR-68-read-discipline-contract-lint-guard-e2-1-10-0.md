# PR #68 — read-discipline contract + lint guard (E2, 1.10.0)

> `feat` · merged 2026-07-26 · by @Nuclominus

## Summary

Track E targets the dominant per-run cost of the pipeline: prompt-cache reads. Caching bills every
token at 0.1× **but on every turn**, so `cache_read ≈ turns × avg_prefix`. Measured on a real
7-phase Android run after the #48 over-count fix: **6.65M cache-read tokens across 117 subagent
turns** — ~27% a fixed floor, **~73% accumulated context** growing to a **101k peak prefix**.

The growth component is agent behaviour, not harness overhead: agents re-read files already in
context, pull whole files where a targeted read would do, and echo verbose tool output back into
their own prefix. Auditing the five agent `.md` files that touch the file system found the guidance
actively **contradicting itself** — `aar-analyst.md` recommended surgical reads in its own
retrospective findings while `developer.md`, `qa-engineer.md`, `security-analyst.md` (two lines)
and `document-writer.md` instructed re-reads or whole-file reads.

This PR resolves that in one place rather than five:

1. **The contract moves into the orchestrator's `=== STABLE PREFIX ===`** — so it is served as a
   cache hit on every subagent turn instead of being restated as fresh per-agent text, and every
   future foundation/framework agent inherits it without editing anything. It draws one explicit
   line: reading from the file system rather than trusting stale prompt state is **kept** (a
   correctness concern); re-reading the same lines, or pulling a whole file when a narrower read
   would do, is **forbidden** (pure cost, no correctness benefit).
2. **Four agent contracts de-contradicted** — `developer`, `qa-engineer`, `security-analyst`,
   `document-writer` now defer to the prefix contract instead of restating and contradicting it.
   Verification switched from "re-read the file" to targeted `grep`, which preserves the
   correctness guarantee the naive "trust the Edit result" wording would have dropped.
3. **A `read-discipline` verb in `tools/sdlc-lint`** checks the anchor is present *and inside the
   stable prefix* (a drift guard, since moving it out would silently break cache stability), and
   scans all 18 agent definitions for the forbidden patterns, with an inline escape-hatch marker
   so a justified exception is auditable rather than the lint being disabled. Wired into
   `sdlc-lint all`; reports 19/19 clean.

Plugin version 1.9.1 → 1.10.0.

## Decisions & rationale

- [[decisions/ADR-0008-read-discipline-contract]] — read discipline as a prefix-level contract
  rather than per-agent prose, checked mechanically rather than only written down.
- **The cost win this PR was built to deliver was subsequently measured and could not be
  demonstrated.** A 20-run A/B (10 per arm, strictly alternating, $7.55) put arm B's cache-read
  median at −10.65% against a **64.2% within-arm spread**; the sign reversed four times as runs
  accumulated. The E2 Definition of Done (`<60k peak prefix`) is met by **both** arms — the
  control's worst run reached 58,184 *without* the contract — so the threshold never discriminated
  on a specimen that size. The contract itself costs ~230 tokens re-read every turn, ≈1.4% of a
  median run. It stays merged on engineering judgement (never worse on any metric measured, and the
  specimen gave read discipline the least surface to act on), **not on evidence**. ADR-0008 carries
  an `UNVALIDATED` banner for exactly this reason; do not cite this PR as a proven cost reduction.
  Full record in `bench/RESULTS.md` and the campaign note landing with #69.
