# PR #228 — maintainer sync for the Android skill matrix (ADR-0036)

> `feat` · merged 2026-09-29 · by @Nuclominus

## Summary

PR 5 of 5: the maintainer side of the Android skill matrix. The matrix is triaged by hand, while
Google's catalog moves on its own. This PR adds the mechanical half of re-syncing the two, so a
person only decides which role gets a new skill.

- **`tools/sdlc-lint/scripts/skill-sets.mjs`** works against any catalog directory: the Android
  CLI's clone, or a checkout of `android/skills`. It never runs the `android` binary.
  - `diff` reports added, removed, relocated and re-dated skills, plus the version change.
  - `refresh` edits, line by line, only the lines it owns: the `source` version and date, and each
    skill's `upstream_path` / `upstream_updated`. The hand-formatted file otherwise stays
    byte-identical.
    - New skills are appended as `TRIAGE`, which lint refuses until they are triaged.
    - A row gone upstream is reported, never deleted. Once it is kept `unassigned`, it counts as
      settled rather than drift.
    - `refresh` refuses to run without a known catalog version, or when two upstream skills share
      a folder name.
  - `render` regenerates the table and the README block.
- **`.claude/commands/android-skills-sync.md`** is the repo command that drives the script. It asks
  for approval on each triage decision, and never runs `android update` or `android skills update`
  without asking.
- **Measured:** `android skills list`, `find` and `--help` do not refresh the CLI's local clone;
  the clone moves with the CLI itself.
