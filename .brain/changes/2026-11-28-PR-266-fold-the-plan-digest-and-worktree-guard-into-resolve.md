# PR #266 — fold the plan digest and worktree guard into resolve

> `perf` · merged 2026-11-28 · by @Nuclominus

## Summary

The orchestrator's start window — Skill call to the `_started_at` anchor, the quantity
ADR-0019's DoD fixes at 2–3 API calls — had two deterministic leaks left. Run 5 measured **4**
calls: a plan carrying a full stack profile (54,746 characters, mostly `profile.prompt_blocks`)
overflowed the harness's inline output limit, and Step 0-large then spent a read call projecting
`CONTEXT` back out of the spilled file. Separately, the worktree-guard check added in #254 ran three
`Bash` calls *before* the anchor, so the window had silently grown to about 7 since run 5. This PR
moves both into the resolver: `resolve/cli.mjs plan --json --digest` keeps Step 0's output inline,
and the resolver computes `plan.worktree_guard`. Expected window: **3** calls (Skill, resolve,
anchor). It is not yet measured — that is run 6.

## What changed

**`plan --json --digest`** (`plugins/sdlc/tools/resolve/digest.mjs`)
- A plan under 20,000 characters prints whole, blocks included, so no dispatch pays an extra call.
- A larger plan goes to a **per-run** `plan_file` in a per-user 0700 directory under tmpdir,
  written 0600 with an exclusive create; two runs in one checkout never share a file, and files
  older than a week are pruned on the next write. The inline digest then omits `prompt_blocks` and
  `skip_rules.signals.changed_files`, the one unbounded list. Android fixture: 44,446 → 11,251
  characters.
- A failed write keeps the plan whole and inline with a `WARN:`; an oversized digest also warns.
  Nothing is written on `--dry-run` or a halt, and `--json` without the flag is byte-identical.

**Two new `cli.mjs` subcommands**
- `block --from <plan_file> --agent <name> [--planning] [--part expertise|skills]` prints one
  agent's expertise and skills blocks as two marked sections, because the 3b-1 template places
  them apart. It is dependency-free, replacing the `jq` read the spilled path used to need.
- `digest --from <file> [--section prints|context]` recovers `CONTEXT` and a usable `plan_file` if
  the harness spills Step 0's output anyway, in two parts if the digest itself overflowed.

**Worktree guard in the resolver** (`plugins/sdlc/tools/resolve/guard.mjs`): Step 2a's rule
unchanged — real cwd under `/.claude/worktrees/` and real `docs/plans` outside the git toplevel —
with a case-insensitive comparison on Windows. The notice reaches `prints[]` once.

**Orchestrator `SKILL.md`.** Step 0 calls `plan --json --digest`; Step 0-large became 0-blocks
(the two block sources, the marker format, `❌ block:` handling, spill recovery); Step 2a runs no
commands; the write-once clock is Step 2's first tool call, with its three-call worktree-guard form
stated there. `commands/start.md` and the anchor comment in `tools/sdlc-lint/lib/start-window.mjs`
follow.

**Review.** The PR went through an in-session review plus three rounds in a separate read-only
session, ending in "No remarks on the code". The rounds caught real defects in the first cut: the
two blocks concatenated into one paste (reordering the stable prefix), one shared `plan_file` per
checkout that a second run would overwrite, a predictable world-readable tmp path, and an unhandled
write error that broke the `--json` stdout contract. `plan.test.mjs` ends at 72 tests;
`dist/antigravity` was regenerated.

**Not yet verified.** The DoD itself (run 6: a clean session, one `/sdlc:start`, no dry run, then
`sdlc-lint start-window`), and the eval suite. A worktree-guarded run measures up to 5 by rule —
the harness refuses the compound clock command — which is documented, not a regression.
