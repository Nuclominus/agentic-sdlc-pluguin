# PR #190 — embed framework providers

> `feat` · merged 2026-09-21 · by @Nuclominus

## Summary

The seven additive Android framework plugins (Retrofit, Ktor, Room, DataStore-Proto, Dagger/Hilt,
Koin, WorkManager) no longer exist as installed plugins. Each is now a row in `android-foundation`'s
new `frameworks:` array, and the resolver synthesizes an ordinary `kind: framework` record from it at
load time. The marketplace drops from 11 entries to 4; `android-foundation` goes to v3.0.0.

The request that started this was "each of them carries nothing more than skills, so they can be
merged" — and that premise was wrong in the one respect that decided the shape of the work. Each
plugin also shipped a manifest whose `enriches_aspect` + `dependency` pair is the conditional-activation
contract: it is what keeps Retrofit guidance out of a Ktor project, Koin out of a Hilt project,
DataStore out of a Room project. Dropping it was rejected; preserving it made this a resolver and
schema change rather than a directory move.

That distinction is not academic. `manifests.mjs` reads exactly **one** manifest per plugin root in
installed mode, while tree mode globs `plugins/**/manifest.yaml`. Moving the directories under the
foundation would therefore have passed CI while silently deactivating all seven frameworks for every
real user — the same tree-vs-installed trap the module header already records biting once before. The
defense is structural, not a test: synthesis lives inside `classify()`, which **both** loaders call,
so the two modes cannot diverge. A dual-mode equality test guards it, and a new `nested-manifest`
lint verb fails on any `manifest.yaml` below a plugin root so the trap cannot be re-created.

Breaking surface: skill ids move into the `android-foundation:` namespace (note the one divergent
case, `dagger-plugin:hilt-conventions` → `android-foundation:hilt-conventions`). There is no runtime
alias layer — per the repo's standing rule a rename happens once, and `/sdlc:doctor` detects stale ids
and *offers* the rewrite, applying nothing without approval. It also reports a stale standalone
install as advisory only, never rewriting the harness-owned `installed_plugins.json`.

A follow-up commit on the same branch closed three review findings: the de-dup tie-break was
order-dependent (and so could itself resolve different winners per mode), `frameworks` carried a
`minItems: 1` that contradicted the scaffolding guidance, and a fixture still used pre-merge ids.
