# PR #160 — patch every framework plugin so the ADR-0021 rename ships

> `chore` · merged 2026-09-08 · by @Nuclominus

## Summary

`/release`'s warn-only version gate earned its keep. Seven framework plugins had content changes in
`release..develop` and not one had moved its version — so the release was cancelled before anything
was pushed, and this fixes the cause.

The changes were not cosmetic. They are the ADR-0021 rename arriving from the framework side:

```diff
-loaded_by: [android-security, android-devops]
+loaded_by: [security-analyst, devops]
```

plus cross-references of the form "defer the encryption strategy to the `android-security` agent".

An installed copy left at its old version keeps rules addressed to agents that no longer exist. No
core role matches the stale `loaded_by`, so the rule reaches nobody — which is the same breakage
[[decisions/ADR-0021-agents-live-in-the-core-foundations-carry-expertise]] exists to repair, only
arriving from the direction nobody was watching. `sdlc` and `android-foundation` were versioned
carefully through eleven PRs; the plugins that merely *mention* an agent were not.

| plugin | | plugin | |
|---|---|---|---|
| `dagger-plugin` | 1.1.0 → 1.1.1 | `retrofit-plugin` | 1.1.0 → 1.1.1 |
| `room-plugin` | 1.1.0 → 1.1.1 | `datastore-proto-plugin` | 1.0.0 → 1.0.1 |
| `koin-plugin` | 1.0.0 → 1.0.1 | `ktor-plugin` | 1.0.0 → 1.0.1 |
| `workmanager-plugin` | 1.0.0 → 1.0.1 | | |

The marketplace's own plugin entries carry no per-plugin version, so there was nothing to keep in
sync there.

## The release is 2.0.0

`1.*` → `2.*` is a breaking change for every consumer — the whole `android-*` roster is gone and
there are no runtime aliases — so the marketplace version follows the plugins rather than taking the
minor bump first proposed. The changelog's breaking-changes block now also tells upgraders to update
the framework plugins, not just `sdlc` and `android-foundation`.

## What this says about the gate

The check is warn-only and stays that way: a content change without a version bump is sometimes
correct (a comment, a test fixture), and a command that refuses to release on it would be worked
around rather than read. What made it useful here is that it *listed the plugins* and left the call
to a human — the fix then belonged in an ordinary PR, not inside `/release`, which is exactly where
it landed.
