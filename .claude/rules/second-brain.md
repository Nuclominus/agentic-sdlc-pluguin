# Rule — Second Brain vault is the source of truth

Applies to work **on this repository** (the SDLC Marketplace codebase), not to the shipped plugin
behavior. The vault lives at `.brain/` (a real Obsidian vault). It is distinct from the
`.obsidian-vault/` template the `manage-vault` skill scaffolds for end-user Android apps — never
conflate the two.

## 1. The vault is the SSOT

`.brain/` is the single source of truth for how this marketplace works and how it evolves:

- **architecture/** — how the system works (absorbed from `ARCHITECTURE.md`, now a pointer stub).
- **components/** — one note per plugin.
- **changes/** — one note per merged PR (auto) + `_moc-changes.md` index.
- **decisions/** — ADRs (the "why").
- **planning/** — roadmap + backlog (absorbed from `CORE-TODO.md`, now a pointer stub).

**Consult the vault before planning or answering architecture/roadmap/decision questions**, and
keep it current as part of the work — don't let it drift. `ARCHITECTURE.md` and `CORE-TODO.md` are
stubs: follow their pointers into `.brain/` rather than editing them.

## 2. A merged PR must be reflected in the vault

The heartbeat: **a merged PR is the trigger to update the docs.**

- On merge to `develop`, the `brain-sync` GitHub Action (`.github/workflows/brain-sync.yml`) runs
  `tools/brain-sync` and opens a follow-up PR (`brain-sync/pr-<n>`) with the auto-generated change
  note + refreshed index.
- The auto note is a deterministic **stub**. **Enrich it**: write a real summary, link the
  `[[decisions/ADR-XXXX]]` it implements, link the `[[planning/roadmap]]` item it advances, and
  update the touched `[[components/<plugin>]]` / `architecture/` notes.
- Run the tool locally when needed: `node tools/brain-sync/cli.mjs sync --pr <n>` (one PR),
  `sync --backfill` (all merged PRs), `reindex` (rebuild `_moc-changes.md` only), `check` (validate
  structure + links + **index completeness**). Tests: `node --test tools/brain-sync/test/*.test.mjs`
  (the trailing-slash dir form does not auto-discover on Node 22). CI runs `check` and these tests
  on every PR.
- **Every content note must be listed in some `_moc-*` index** — its pillar's MOC, or `_moc-root.md`
  for `components/`. `check` fails on one that is not. A note nothing links *to* still resolves all
  its own links and passes every other test, yet is unreachable by anyone browsing the vault: that
  is how ADR-0014 and ADR-0015 both shipped unlisted while `check` reported "clean". Adding an ADR
  therefore means adding its MOC row in the same commit.
- **Never leave a brain-sync PR unmerged while you merge the next feature PR.** Merging to
  `develop` triggers the Action, which opens the next `brain-sync/pr-<n>` immediately — so an
  outstanding one becomes *two open at once*, and the conflict below is guaranteed. The order that
  avoids it: **merge the outstanding brain-sync PR first, then the feature PR.** The new stub then
  opens alone, against a `develop` that already carries the previous index row, and there is nothing
  to collide with. (Confirmed 2026-08-04: #120 merged 14 s before #121; #122 opened clean, no
  `reindex` needed.)
- **Two brain-sync PRs open at once will conflict on `_moc-changes.md`** — both append a row, so
  merging `develop` into the second one collides every time. This is the *repair*; the bullet above
  is the *prevention*, and it is cheaper. Resolve it with `reindex`, never by
  hand and never with `sync --backfill`: backfill rewrites *every* note from its PR and destroys the
  enriched prose. Take `develop`'s copy of the index, run `reindex`, commit.

## 3. Non-trivial decisions get an ADR

Record a meaningful design/architecture decision as an ADR in `.brain/decisions/`
(`_templates/adr.md` shape: `adr`, `status`, `date`, context / decision / consequences). The change
note(s) that implement it link the ADR; the ADR references implementing PRs as plain text (e.g.
`#12`) — **not** `[[changes/...]]` wikilinks.

## 4. Never hand-edit machine-owned content

- Change-note **frontmatter** and `changes/_moc-changes.md` are machine-owned — generated by
  `tools/brain-sync`. Do not hand-edit them; re-run the tool instead (it is deterministic and
  idempotent: exactly one note per PR).
- Enrich only the **prose** sections of a change note (below the auto Summary).
- Keep `node tools/brain-sync/cli.mjs check --vault .brain` **clean** before merging vault changes.
